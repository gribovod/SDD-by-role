# Чек-лист пограничних випадків

Зібрано на розборі пілоту, з якого виріс цей підхід: саме ці питання «вистрілили» пізно —
після звірки з кодом або вже під час розробки — і коштували найбільше переробок. Доповнюйте
список уроками своєї команди (окремим MR).

**Як користуватися.** БА проходить кожен розділ (скіл `/sdd-ba` робить це в інтерв'ю).
Для кожного пункту в `spec.md` → «Пограничні випадки» записується **або правило, або
«не стосується» з причиною**. Пункт, позначений 🔧, — це питання до розробки, а не до замовника:
не вгадуйте, ставте маркер `[ПОТРЕБУЄ УТОЧНЕННЯ]`.

## 1. Ролі й доступ

- [ ] Хто бачить нову функцію, а хто ні (користувач, адміністратор, неавторизований відвідувач)?
- [ ] Хто може **запускати** дію, а хто лише **бачить** результат?
- [ ] Що бачить адміністратор, який увійшов **під обліковим записом користувача**? 🔧 *(з пілоту: два різні способи входу «під користувачем» поводилися по-різному)*
- [ ] Ролі «лише перегляд» (підтримка, аудитор) — що бачать?
- [ ] Чи бачить користувач те, що бачить адміністратор (і навпаки)? *(з пілоту: внутрішні оцінки адміністратора користувачу не показуються)*

## 2. Стани й статуси

- [ ] У яких статусах об'єкта (замовлення, профілю, заявки) функція доступна, а в яких прихована?
- [ ] Що відбувається **після** зміни статусу (подання, підтвердження, завершення)?
- [ ] Чи змінює фіча чинні статуси й переходи? За замовчуванням — **ні** (конституція, розділ 8).
- [ ] Чи нові позначки фічі можна сплутати з чинними статусами? Якщо так — інша назва + словник. *(з пілоту: «Статус перевірки» → «Результат перевірки»)*
- [ ] Які статуси існують насправді? 🔧 *(з пілоту: виявилось, що дані змінюються і в статусі, який вважали остаточним)*

## 3. Зміна даних після дії

- [ ] Користувач змінив дані **після** того, як функція відпрацювала: результат скидається, лишається чи позначається як застарілий?
- [ ] Повторний запуск: обробляється все заново чи лише змінене?
- [ ] Користувач уже ввів значення вручну — чи може автоматика його перезаписати?
- [ ] Додали й одразу видалили — це «зміна»?
- [ ] Що можна змінити на екрані насправді (наприклад, тип документа без заміни файлу)? 🔧 *(з пілоту: змінити тип без заміни файлу було неможливо)*

## 4. Збої й час

- [ ] Зовнішній сервіс не відповів / повернув помилку — що бачить користувач, що зберігається?
- [ ] Відповідь прийшла пізніше, ніж ми перестали чекати?
- [ ] Подвійне натискання, запуск з двох вкладок одночасно.
- [ ] Скільки користувач готовий чекати і що бачить під час очікування? *(у spec — словами для користувача; секунди й ліміти — у design)*
- [ ] Збій не має ламати чинний процес: користувач може продовжити без функції?

## 5. Файли й формати

- [ ] Які формати приймаємо? Що з файлами інших форматів — відхиляємо, ігноруємо, показуємо «не підтримується»?
- [ ] Нечитабельний, порожній, обрізаний, перевернутий файл.
- [ ] Багатосторінковий документ; документ із кількох файлів (дві сторони картки).
- [ ] Великий файл, багато файлів одночасно.
- [ ] Підписані, зашифровані, запаковані файли (електронний підпис, архіви). 🔧 *(з пілоту: підпис файлів виявився штатною функцією системи, про яку не знали)*
- [ ] Як система визначає формат? 🔧

## 6. Вмикання й розгортання

- [ ] Чи потрібен вимикач (по категоріях, по продуктах, по клієнтах) без релізу?
- [ ] Що відбувається з уже накопиченими даними, коли функцію вимкнули?
- [ ] Для яких категорій / сегментів на старті? Чи всі записи категорії однаково позначені в системі? 🔧 *(з пілоту: у давніх записах поле категорії було порожнім)*

## 7. Дані, аналітика, персональні дані

- [ ] Що зберігаємо, скільки часу, хто має доступ?
- [ ] Чи є персональні дані? Де вони обробляються, чи зберігаються проміжні результати, чи йдуть до сторонніх сервісів?
- [ ] Як рахуватимемо метрику успіху з L1 — звідки беруться дані?
- [ ] Тестові дані — лише вигадані особи (конституція, розділ 9).

## 8. Тексти

- [ ] Кожен стан, який бачить користувач, має текст (успіх, помилка, очікування, «не перевірено», «застаріло»).
- [ ] Тексти не обіцяють більше, ніж робить система (наприклад, «до хвилини», коли реально до двох).

## 9. Вплив на чинний функціонал

- [ ] Які екрани, списки, фільтри, вивантаження (Excel, звіти) зачіпає фіча?
- [ ] Чи треба показувати новий результат у списках, фільтрах, вивантаженнях?
- [ ] Чи знайдено дефекти чинного функціоналу по дорозі? Якщо виправляємо в цій задачі — записати окремо як «супутнє виправлення» з рішенням ПМ.
