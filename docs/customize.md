# Налаштувати репозиторій для своєї команди

Для адміністратора команди (техлід або ПМ), один раз. ~30 хвилин. Далі учасники команди
проходять лише [перше налаштування](setup.md).

## 1. Свій репозиторій специфікацій

1. Створіть **порожній** репозиторій у своєму GitLab чи GitHub — наприклад, `specs` або `PM`.
   Він буде спільним для всіх продуктів команди.
2. Склонуйте цей каркас і перенаправте на свій репозиторій:

   ```bash
   git clone <адреса цього каркасу> specs
   cd specs
   git remote set-url origin <адреса вашого репозиторію>
   git push -u origin main
   ```

3. Приберіть шаблон MR платформи, якою не користуєтесь: `.gitlab/` (якщо GitHub) або
   `.github/` (якщо GitLab).

## 2. Налаштування команди в `CLAUDE.md`

Заповніть таблицю **«Налаштування команди»** на початку [`CLAUDE.md`](../CLAUDE.md):

| Параметр | GitLab | GitHub |
|---|---|---|
| Платформа | `gitlab` | `github` |
| Адреса | `https://gitlab.ваша-компанія.com` | `https://github.com` (або адреса GitHub Enterprise) |
| Репозиторій специфікацій | `група/specs` | `організація/specs` |
| ID репозиторію | Settings → General → Project ID | — |
| Основна гілка | `main` | `main` |
| Змінна з токеном | `GITLAB_API_TOKEN` (або своя назва) | — (`gh auth login`) |

Поки в таблиці лишаються `<…>`, Claude попереджатиме, що репозиторій не налаштовано.
Якщо основна гілка у вас не `main` — замініть `main` у `CLAUDE.md` і в документації пошуком.

Закомітьте зміни (це ще можна в `main` напряму — захист гілки вмикаємо далі).

## 3. Продукти

Продукт — система, для якої пишуться специфікації (сайт, застосунок, сервіс). У кожного своя
папка `SDD/<продукт>/` з карткою:

1. Скопіюйте [`SDD/templates/product/`](../SDD/templates/product/) у `SDD/<продукт>/` — коротка
   назва латиницею, наприклад `SDD/shop/`.
2. У `SDD/<продукт>/README.md` заповніть:
   - **Трекер** — проєкт, де живуть задачі продукту (може відрізнятися від репозиторію
     специфікацій);
   - **Код** — репозиторій і гілка, яку читає `/sdd-code-check`. Гілку підтверджує розробка;
   - **Мітки** — для питань до розробки й замовника (див. п. 5).
3. Додайте продукт до таблиці «Продукти» в [`SDD/README.md`](../SDD/README.md).

Можна не робити це заздалегідь: `/sdd-pm` сам запропонує створити картку, коли зустріне
новий продукт.

Папка `system/` спершу порожня — її наповнює розробка фактами з коду в ході фіч. Якщо вже
є документація системи, яку розробка готова підтвердити, — можна перенести її туди одразу
(кожен факт — із джерелом і датою).

## 4. Права й захист основної гілки

Головне правило процесу — **в основну гілку потрапляє лише погоджене, і вливає ПМ**.

| | GitLab | GitHub |
|---|---|---|
| Учасники (ПМ, БА, розробка, QA) | роль **Developer** — пушать гілки, створюють MR | роль **Write** |
| Хто вливає | ПМ — **Maintainer** | ПМ — **Maintain** або в списку дозволених у правилі гілки |
| Захист `main` | Settings → Repository → Protected branches: push — *No one*, merge — *Maintainers* | Settings → Branches (Rulesets): *Require a pull request before merging*, за бажанням — *Require approvals* |
| Шаблон опису | `.gitlab/merge_request_templates/SDD.md` — обирається в MR | `.github/pull_request_template.md` — підставляється сам |
| Замовник | **Reporter** — читає й коментує | **Read** (для приватного репозиторію) — читає й коментує |

## 5. Мітки в трекерах продуктів

Скіли пропонують позначати задачі мітками `Питання до розробника` і `Питання до замовника`.
Створіть їх у трекері кожного продукту або впишіть у картку продукту свої. Якщо міток немає —
Claude напише питання коментарем у задачі; нових міток сам не створює.

## 6. Адаптація процесу

Каркас — стартова точка. Що варто переглянути під себе (кожну зміну — окремим MR, як і спеки):

| Що | Де | Приклад зміни |
|---|---|---|
| Правила гри: ролі, ліміти, режими, гейти | [`SDD/constitution.md`](../SDD/constitution.md) | інший ліміт питань за сесію; QA погоджує ще й design |
| Уроки своєї команди | [`SDD/checklists/edge-cases.md`](../SDD/checklists/edge-cases.md) | розділ про мобільні застосунки, локалізацію, платежі |
| Хто наступний | [`SDD/checklists/next-step.md`](../SDD/checklists/next-step.md) | окремий крок дизайнера |
| Форма документів | [`SDD/templates/`](../SDD/templates/) | розділ «Макети» в spec |
| Поведінка Claude | [`.claude/skills/`](../.claude/skills/), [`CLAUDE.md`](../CLAUDE.md) | інша нумерація гілок, інший формат комітів |
| Мова | усі файли | переклад шаблонів і скілів; у `CLAUDE.md` змініть рядок «Мова відповідей і документів» |

Скіли посилаються на конституцію, шаблони й чек-листи за назвами розділів — змінюючи їх,
перевірте посилання (пошук за назвою розділу по репозиторію).

## 7. Перевірка

1. Відкрийте репозиторій у VS Code з Claude Code, наберіть `/sdd` — мають з'явитися п'ять скілів.
2. Скажіть Claude: «перевір налаштування репозиторію» — він прочитає `CLAUDE.md` і перевірить
   доступ до платформи (токен або `gh`).
3. Пройдіть [навчальну фічу](solo-walkthrough.md) самі — до MR включно. Це найкраща перевірка
   прав і налаштувань.
