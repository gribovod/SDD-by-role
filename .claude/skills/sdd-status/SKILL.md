# /sdd-status · фічі в роботі

Ти показуєш, де кожна фіча і хто ходить наступним. **Лише читання**: не перемикай гілки, не
комітить, нічого не змінюй у трекері. Пиши українською.

## Крок 1. Звідки брати дані

1. `git fetch --prune origin` (дозволено — це не змінює робочу копію).
2. **Відкриті MR репозиторію специфікацій** (`CLAUDE.md` → «Налаштування команди» і «Робота з
   платформою») — усі, зокрема чернетки. Для кожного: обговорення (скільки, які ще не закриті)
   і погодження (хто схвалив; якщо платформа їх не віддає — пропусти).
3. **Гілки** `origin/sdd/*` і локальні `sdd/*` без MR (локальна без `origin` — «не відправлено»).
4. **Файли фічі** читай без перемикання: `git show origin/<гілка>:SDD/<продукт>/changes/<N>-<назва>/<файл>`.
   Папку фічі знайди через `git ls-tree -d --name-only origin/<гілка> SDD/*/changes/`.
5. Навчальні фічі (`0000-training-*`) і службові гілки без папки фічі (правки скілів, docs) —
   пропускай, якщо користувач не попросив «усе».

Якщо користувач просить «мої» — лиши фічі, де він автор MR (поточний користувач: GitLab — `GET /user`, GitHub — `gh api user`) або
автор комітів гілки.

## Крок 2. Що визначити по кожній фічі

| Поле | Як |
|---|---|
| Фіча | номер задачі, продукт, назва — заголовок `proposal.md` |
| Крок | які файли є: лише `proposal.md` → proposal; є `design.md` з фактами → факти; є `spec.md` → spec; заповнені «Рішення» / «Контракти» → design; влито → Гейт 1 / Гейт 2 |
| Чекає рішення | `ПМ ⏳` / `БА ⏳` у «Наслідках» `design.md`; ТР з ⬜ |
| Питання до розробки | рядки таблиці «Питання до розробки» в `proposal.md` з порожньою «Відповідь розробки» |
| Маркери / припущення | `[ПОТРЕБУЄ УТОЧНЕННЯ` у `spec.md`; рядки «Припущення» без ✅ |
| MR | чернетка / на погодженні; незакриті обговорення; хто схвалив |
| Оновлено | дата останнього коміту гілки |

## Крок 3. Хто наступний

Визнач за `SDD/checklists/next-step.md` — перше правило, що спрацювало. Це те саме джерело,
яким користуються всі скіли, тож `/sdd-status` і скіли не можуть сказати різне.

## Крок 4. Відповідь

Одна таблиця, найсвіжіші зверху:

| Фіча | Крок | MR | Відкрито | Наступний |
|---|---|---|---|---|
| #42 shop · Експорт замовлень | spec | MR 8 на погодженні | 2 обговорення | БА — відповісти на коментарі |

Під таблицею — лише те, що потребує уваги: зависло понад тиждень без комітів; гілка не
відправлена на сервер; MR без посилання на задачу. Наприкінці — одна пропозиція: з якою фічею
працювати першою і якою командою почати.
